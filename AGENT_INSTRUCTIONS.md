# Агентская инструкция: собрать веб-приложение «Вкус дома»

## 0. Роль и результат

Ты — ведущий frontend-разработчик и UI-инженер. Твоя задача — **сверстать работающий mobile-first интерфейс веб-приложения «Вкус дома»**: личной и общей кулинарной книги в эстетике домашнего Прованса.

В результате должен получиться аккуратный, запускаемый локально фронтенд с кликабельной навигацией, реалистичными демо-данными и всеми ключевыми экранами MVP. Сначала обеспечь ясную работу сценариев, затем доведи визуальную часть до соответствия референсам.

Это не задача «сделать похожую фиолетовую страницу». Нужен цельный, спокойный продукт: тёплая домашняя книга рецептов, где главное — блюдо, рецепт и удобство приготовления.

## 3. Технологический ориентир

Используй современный статический frontend, пригодный к хостингу на Timeweb Cloud App Platform:

- React + TypeScript + Vite;
- CSS Modules или обычный структурированный CSS с CSS-переменными; не разбрасывай inline-стили;
- React Router для маршрутов;
- локальное хранилище (`localStorage` или IndexedDB) за репозиторием данных, чтобы его потом можно было заменить API;
- SVG-иконки из одного согласованного набора (Lucide или эквивалент) и локальные/разрешённые веб-шрифты.

Не подключай UI-kit, который диктует чужую визуальную систему. Tailwind допустим только если переменные, компоненты и результаты полностью следуют этой инструкции; предпочтительнее собственные токены и компоненты.

### Минимальная структура

```text
src/
  app/                 # маршрутизация и провайдеры
  components/          # переиспользуемые UI-компоненты
  features/            # recipes, favorites, notes, profile
  data/                # seed-данные и справочники
  lib/                 # helpers, formatters, repository
  pages/               # экраны маршрутов
  styles/              # tokens.css, global.css, fonts.css
public/
  images/              # оптимизированные локальные изображения/плейсхолдеры
```

Не помещай бизнес-логику в компоненты страниц. Выдели типы `Recipe`, `Ingredient`, `RecipeStep`, `Category`, `RecipeSource` и репозиторий с понятными методами чтения/записи.

## 4. Обязательные экраны и сценарии

### 4.1 Общая книга — `/`

- Верхняя воздушная зона: знак/название «Вкус дома», небольшая акварельная чашка или веточка, ненавязчивое приветствие.
- Блок «Рецепт дня» или сезонный рецепт: большая карточка с фото, названием, временем и переходом в рецепт.
- Раздел «На любой случай» / категории: карточки категорий с ненавязчивыми ботаническими иллюстрациями.
- Нижняя навигация: «Общая книга», «Мои рецепты», «Избранное», «Профиль».

### 4.2 Каталог рецептов — `/recipes`

- Крупный заголовок «Рецепты», компактный верхний ботанический декор.
- Поиск по названию рецепта с моментальной фильтрацией.
- Горизонтально прокручиваемые чипы: «Все», «Завтраки», «Закуски», «Супы», «Салаты», «Горячее», «Гарниры», «Соусы», «Выпечка», «Десерты», «Напитки», «Заготовки», «Полуфабрикаты».
- Список карточек рецептов: фото, название, категория; время допустимо как дополнительная информация. Не добавляй рейтинг.
- Пустой результат поиска: доброжелательная акварельная иллюстрация, текст и действие «Сбросить поиск».

### 4.3 Детальный рецепт — `/recipes/:id`

- Hero-фото блюда. Кнопки «Назад» и «В избранное» должны быть контрастны поверх фото и иметь доступные подписи.
- Название, ботанический разделитель, время, порции, сложность.
- Контрол порций: уменьшение/увеличение с корректным пропорциональным пересчётом ингредиентов. Базовое значение рецепта всегда сохраняется отдельно.
- Секции: «Ингредиенты», «Приготовление», а для общих рецептов — «Мои заметки».
- Список ингредиентов: название, количество и единица измерения; на мобильном не ломается при длинных названиях.
- Нумерованные шаги приготовления с длительностью шага, если она есть.
- Личный рецепт можно редактировать и удалить (с подтверждением); общий — только просматривать, добавлять в избранное и вести личную заметку.
- Личным рецептом можно поделиться: на данном этапе сделай корректную имитацию — Web Share API, при его отсутствии копирование локальной ссылки с понятным уведомлением. Не создавай публичный серверный share-link без бэкенда.

### 4.4 Мои рецепты — `/my-recipes`

- Список только личных рецептов пользователя.
- Основная кнопка «Добавить рецепт» внутри этого раздела.
- Состояние без рецептов: акварельная заглушка, краткое объяснение, CTA добавить первый рецепт.
- Переходы к просмотру и редактированию.

### 4.5 Добавление и редактирование — `/my-recipes/new`, `/my-recipes/:id/edit`

Организуй форму смысловыми блоками:

1. Основное: название*, категория*, автор (опционально), порции*, общее время*.
2. Главная фотография: превью, выбор, замена, удаление. На этом этапе допустимо хранить локальный object URL/Data URL с ограничением размера и понятной подсказкой.
3. Ингредиенты*: добавление, удаление, название, количество, единица. Единицы только: `г`, `кг`, `мл`, `л`, `шт.`, `ст. л.`, `ч. л.`, `стакан`.
4. Шаги*: добавление, изменение порядка, текст, длительность шага.
5. Для категории «Полуфабрикаты»: обязательные блоки заморозки/после разморозки, срок и условия хранения.
6. Сохранение и отмена без потери данных (предупреди при уходе с несохранёнными изменениями).

Покажи валидацию только после взаимодействия пользователя или попытки сохранения. Сообщения об ошибках должны быть конкретными и расположены рядом с полем.

### 4.6 Избранное — `/favorites`

- Единый список общих и личных сохранённых рецептов.
- Удаление из избранного доступно с карточки и из детального экрана.
- Пустое состояние с ясным объяснением и переходом к каталогу.

### 4.7 Профиль — `/profile`

- Спокойный экран с демонстрационными данными пользователя, номером телефона в маскированном формате и кнопкой «Выйти».
- Подпись о том, что реальные вход и SMS-подтверждение будут подключены позднее; не создавай фальшивую форму авторизации как работающую безопасность.

### 4.8 Страницы/состояния качества

- Маршрут 404 с возвращением в общую книгу.
- Skeleton или другой ненавязчивый loading-state для списков, если данные загружаются асинхронно.
- Error-state на уровне данных с кнопкой повторной попытки.
- Toast/inline feedback для «Сохранено», «Добавлено в избранное», «Ссылка скопирована».

## 5. Безусловные визуальные правила

### Палитра

Создай токены ровно с такими исходными значениями:

```css
:root {
  --color-canvas: #FAF7F1;
  --color-surface: #FFFCF8;
  --color-surface-muted: #F3EFE7;
  --color-lilac-50: #EEE9F2;
  --color-lilac-100: #DDD3E6;
  --color-lavender: #A995C2;
  --color-plum: #756181;
  --color-ink: #514C49;
  --color-ink-muted: #7D7670;
  --color-sage: #AAB69E;
  --color-olive: #7E8A70;
  --color-terracotta: #C98270;
  --color-danger: #AD665E;
  --color-border: #DED5D1;
}
```

Обычный экран состоит преимущественно из кремовых поверхностей. Лавандовый — главный интерактивный цвет; шалфейный и оливковый — вспомогательные природные акценты; терракота — редкий CTA/статусный акцент. Не используй чистые #000 и #FFF как основные цвета.

### Типографика

- Заголовки и названия блюд: **Cormorant Garamond**, вес 500.
- Интерфейс, формы, метаданные и длинный текст: **Manrope**, веса 400–600.
- Обязательно подключи кириллические начертания и настрой качественные fallback: Georgia и Arial/sans-serif.
- Display: 52–64 px; H1: 40–48 px; H2: 32–36 px; H3: 26–30 px; body: 16 px; подписи: 12–14 px.
- Не используй капс в заголовках, рукописные шрифты или тяжёлый bold как декоративный приём.

### Сетка и поверхности

- Mobile-first: проверить ширины 360, 390 и 430 px; затем 768 и 1280 px.
- Боковые отступы: 20 px, в плотных списках 16 px. Шкала промежутков: 8/12/16/24/32/48 px.
- Карточки: фон `--color-surface`, радиус 24 px, рамка 1 px `--color-border`, тень `0 6px 18px rgba(91, 72, 88, 0.08)`.
- Плитки категорий: радиус 20 px; чипы — pill/radius 999 px.
- Основная кнопка высотой не менее 48 px, предпочтительно 56 px; все touch-цели не меньше 44×44 px.
- Нижняя навигация на mobile фиксированная: 76–88 px плюс safe area. Добавь `padding-bottom`, чтобы она не закрывала контент.

### Декор и изображения

- Применяй единый стиль: акварель с лёгким карандашным контуром. Мотивы — лаванда, шалфей, олива, фарфор, кухня, лен.
- Декор располагается только по краям и в свободных полях. Центральная зона, формы, кнопки и текст остаются чистыми.
- На одном экране не более 2–4 крупных декоративных мотивов. Никаких emoji, 3D-иконок, фотоколлажей и смешения стилей.
- Льняная фактура допустима на фоне с прозрачностью 3–6%. Шторы — только в hero/обложках, не на всех экранных формах.
- Фото блюд: тёплый естественный свет, керамика/лен/дерево, натуральные цвета, крупное аппетитное блюдо. Не использовать чёрный фон, HDR, ресторанный глянец и холодную цветокоррекцию.
- Если нет прав на использование готовой фотографии, используй нейтральную фирменную акварельную заглушку. Не вставляй случайные изображения с поиска без лицензии.

### Компоненты

- `RecipeCard`, `CategoryTile`, `BottomNav`, `SearchField`, `FilterChip`, `PrimaryButton`, `SecondaryButton`, `IconButton`, `IngredientList`, `ServingsControl`, `EmptyState`, `BotanicalDivider`, `RecipeForm` должны быть переиспользуемыми компонентами.
- Иконки — тонкие контурные, с округлыми окончаниями, толщина около 1.75–2 px. Навигация: дом, книга, сердце, профиль.
- Primary button: `--color-lavender` и белый текст. Secondary: кремовая поверхность, лиловая рамка, сливовый текст. Quiet: прозрачная.
- Форма и поиск: высота 56 px, радиус 20–24 px, светлая поверхность, тонкая лиловая граница. Не делай стандартные браузерные поля без стилизации.
- Разделители — тонкая линия и маленькая ботаническая виньетка только между крупными блоками, не после каждого абзаца.

### Запреты

- Неон, яркие градиенты, glassmorphism, резкие тени, тёмные полноэкранные фоны.
- Декоративные элементы, перекрывающие контент; текст поверх пёстрой фотографии без подложки.
- Карточки, перегруженные бейджами, подробностями и иконками.
- Копирование референсов пиксель-в-пиксель в ущерб реальному содержимому и адаптивности.

## 6. Данные и поведение

### Демо-данные

Подготовь не меньше 10 правдоподобных русскоязычных рецептов из разных категорий. Среди них обязательно: паста с томатами, сырники с ягодами, лосось с овощами. У каждого должны быть осмысленные ингредиенты и шаги.

Раздели данные на:

- общие рецепты (`source: 'shared'`);
- личные рецепты (`source: 'personal'`, `ownerId` текущего пользователя);
- избранное как отдельный набор идентификаторов;
- заметки как отдельные личные записи, привязанные к `recipeId`.

### Поведение

- Избранное должно сохраняться между перезагрузками браузера.
- Личный рецепт можно создать, отредактировать и удалить; изменения сразу сохраняются локально.
- Общий рецепт нельзя редактировать из пользовательского интерфейса.
- Поиск не должен требовать кнопки «Найти»: он фильтрует по мере ввода, регистронезависимо.
- При изменении порций не меняй исходные значения рецепта: вычисляй отображаемые количества из базовых.
- Обработай дробные количества разумно: максимум один знак после запятой, без ложной точности.
- Не использовать рейтинг: он не входит в MVP, даже если есть на референсе.

## 7. Доступность и качество

- Семантическая HTML-разметка: `main`, `nav`, `header`, `button`, `label`, корректные заголовки.
- В видимом фокусе не должно быть потери контраста. У интерактивных элементов есть hover, active, focus и disabled-состояния.
- Контраст основного текста соответствует WCAG AA. Цвет никогда не является единственным признаком ошибки или активного состояния.
- У иконок-кнопок есть `aria-label`; декоративная графика имеет пустой `alt`; у фото блюд — полезный `alt`.
- Учти `prefers-reduced-motion`; длительность обычных анимаций 160–240 ms, без шумной пружинистости.
- Не допусти горизонтальной прокрутки страницы на 360 px. Горизонтальная прокрутка допустима только у ряда чипов категорий.
- Оптимизируй изображения, добавь `loading="lazy"` за пределами первого экрана и размеры, предотвращающие layout shift.

## 8. Процесс работы

1. Изучи файлы из раздела 1 и коротко перечисли принятые решения в `README.md`.
2. Инициализируй проект и настрой запуск, проверку типов и production-сборку.
3. Сначала реализуй токены, шрифты, глобальные стили и базовые компоненты.
4. Затем реализуй маршруты и данные; после этого — экраны и сценарии.
5. Проверь mobile-версию по трём референсам визуально: ритм, воздух, типографику, приоритет блюда и умеренность декора.
6. Прогони линтер/проверку типов/production build. Исправь все ошибки.
7. Обнови `README.md`: запуск, структура, сценарии, ограничения мок-данных и деплой-подготовка.

Не останавливайся после статичной главной страницы. Выполни весь перечисленный MVP-интерфейс. Если часть невозможна без сервера, реализуй честную локальную версию, пометь это в README и не выдавай её за защищённую серверную функцию.

## 9. Подготовка к будущему размещению на Timeweb

Развёртывание произойдёт позднее, когда владелец предоставит доступы. Сейчас нужно только подготовить проект:

- production build должен создавать каталог `dist`;
- в `README.md` укажи команды установки, проверки и сборки;
- добавь `.env.example` только для переменных, которые действительно потребуются позднее; не создавай и не коммить `.env` с секретами;
- не вшивай адрес будущего домена в код. Используй относительные пути и конфиг окружения при необходимости;
- SPA-маршруты должны быть готовы к fallback на `index.html`; опиши это как требование для настройки хостинга;
- подготовь краткий чек-лист «Timeweb deployment», но не выполняй его без доступа: подключить репозиторий, выбрать Frontend/React или статический frontend, задать build-команду и каталог `dist`, проверить технический домен и SPA fallback, затем привязать домен.

Ориентир: Timeweb Cloud App Platform может собирать frontend из репозитория и выдаёт технический домен с SSL; для уже собранных HTML/CSS/JS проектов публикация идёт из каталога статических файлов. Перед реальным деплоем всегда сверяй актуальные настройки с официальной документацией Timeweb.
